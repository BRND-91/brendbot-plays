# How the bot is built

The agent plays Pokémon ROWE, a closed build of pokeemerald-expansion, with no human at the
controls. It boots the ROM in a headless mGBA build, reads the game's state out of RAM and the
ROM's static tables, decides what to do next, and drives real button presses one frame at a
time. It plays through the actual UI the way a person would. The only RAM writes are fixture
staging in tests, never gameplay shortcuts.

This file is the map: which module and which symbol holds a thing, so a lookup is a targeted
read or one `grep -n "def <name>"`, never a cold sweep of the 2800-line `play.py` and 30-odd
modules. When this file and the code disagree, the code wins and this file is stale.

## Control flow

A single run is a supervisor around one executor process, both reading and rewriting a handful
of files under `agent/states/`.

1. `run-grind.sh [hours]` loops for a wall-clock budget. Each iteration runs the planner, then
   launches the executor, waits for it to exit (stall, crash, timer, or a terminal exit reason),
   and relaunches from the saved state. All runs append to `states/grind.log` (rotated at 50M,
   one kept). It traps TERM/INT to stop, and exits the whole supervisor on an `unsupported*` or
   `no_grass_idle` exit reason.
2. `planner.py --apply` reads `states/status.json`, decides the next goal, and writes
   `states/goal.json`. The goal is re-decided before every launch, so a goal the executor reached
   (or a grind it demoted itself to) never outlives the run that wrote it.
3. `play.py --state states/live.ss` runs the loop: read state, pick an action toward the goal,
   press it, repeat. It rewrites `states/status.json` and `states/live.ss` only at responsive
   moments, so a crash mid-menu resumes from the last clean frame.
4. `stream_sink.py` pushes the emulator's frames and audio into the HLS stream Caddy serves at
   live.brenergy.net.

The state files under `states/`:
- `live.ss` is the save the supervisor relaunches from and the executor rewrites in place.
- `status.json` is the executor's published state (map, tile, party, badges, field_moves, goal,
   exit_reason, pid). The planner and any status claim read this, never the logs alone.
- `goal.json` is the planner's decision for the next launch.
- `map_graph.json` is the learned world graph (walked borders plus gated edges), saved atomically
   with no backup.
- `grind_blocked.json` is the set of grass maps the executor gave up reaching.
- `gym_closed.json` is gyms recorded unclearable, with the condition that reopens each.
- `stuck_hits.json` counts repeated crossing failures per edge toward a gate.
- `live/` is a timestamped snapshot ring plus a kept 7-badge playable save.
- `fixtures/` are frozen savestates the tests and probes replay.

## Repo layout

- `agent/` is everything the bot runs to play: the emulator boot layer, the RAM and ROM readers,
  the pathfinder, the battle and catch logic, the planner, the executor loop, the errands, the
  tests, and the probes.
- `ARCHITECTURE.md` (this file) explains how it is built and where each feature lives.
- `README.md` is the front page and the nav-map explanation.
- `index.html` is the interactive nav map, generated by `agent/gen_nav_map.py`, also hosted on
  Pages.

## The code, by layer

### Emulator boot and I/O
- `emu_boot.py` loads the locally built libmgba and its cffi binding and exposes `class Emu`
  (`run`, `tap`, `read`, `u32`, `write`, `ewram`, `iwram`, `save_state`, `load_state`,
  `save_png`). Import it before `mgba` anywhere else. The ROM path is pinned here.
- `drive.py` steps the ROM from a save state, applies an input script
  (`A,w120,START,UP*3,hold:A:60`), and snapshots the result. The manual tool behind most probes.
- `stream_sink.py` (`class FrameStreamer`) scales each 240x160 frame 3x, encodes AAC audio, and
  emits rolling 2s HLS segments. `play.py`'s `NullStreamer` is the `--no-stream` stand-in.

### Reading the game
- `rowe_symbols.py` is the RAM address map. ROWE ships no `.sym`, so each address carries how it
  was established: observed live, found as a Thumb literal in the ROM, or matched against the
  vendored decomp source.
- `rowe_state.py` gives typed RAM reads. `class GameState` is the reader the executor holds:
  `position`, `party`, `box`/`boxes`, `in_battle`, `badges`, `flag`, `money`, `bag_pocket` and
  the pocket helpers (`poke_balls`, `medicine`, `tms`, `key_items`, `shop_items`), plus the
  battle-screen reads the menu logic turns on (`callback2`, `controller_func`, `chooser`,
  `choosing`, `comm`, `in_move_list`, `in_selection_script`, `move_cursor`, `action_cursor`,
  `party_menu_slot`, `battlers`, `battle_type_flags`, `battle_outcome`, `disabled_move`).
  `class PartyMon`/`BattleMon`/`BoxMon` are the typed rows.
- `rowe_rom.py` reads the static ROM tables, offsets located by fingerprinting known vanilla
  entries, valid for this build only. Mechanics: `move`, `species`, `stats_at`, `level_from_exp`,
  `type_chart`, `effectiveness`, `evolutions`, `level_up_learnset`, `egg_moves`, `tm_learnset`,
  `tm_move`, `ability_of`, `nature_modifier`. Maps: `map_header`, `map_connections`, `map_warps`,
  `map_cells`, `metatile_behavior`, `map_objects`, `map_music`, `is_underwater`, `is_indoor`,
  `is_center`, `is_mart`, `wild_land_levels`, `gym_maps`. Trainers: `trainer_pool`, `leader_team`,
  `leader_build`. The routing graph: `world_edges` (the full static graph), `passthroughs`, and
  `dive_script_edges` which decodes each map's dive-warp script for the `setdivewarp` targets the
  connection and warp tables never carry.
- `rowe_map.py` reads the current map's live header: warps, connections, coord events, item balls.
- `rowe_live.py` is the live-run status reader used by status claims and probes.

### Rendering art
- `icons.py` renders party-menu mon icons and type badges as the game draws them.
- `sprites.py` renders species front sprites, normal and shiny, as transparent PNGs.

### Navigation
- `nav.py` is the overworld pathfinder. `class Grid` reads the current map plus its connection
  margin and answers passability: `passable`, `reachable`, `region`, `path` (BFS), plus the water,
  ledge, elevation, and ride rules in `_step_refused`/`_ride`/`_ledge_hop`/`_carry`, and the dive
  and surface sets `dive_tiles`/`emerge_tiles`. On an underwater map it treats deep water as
  walkable floor rather than surf-only water. `class Navigator` walks a path one tile at a time
  (`walk_to`, `step`, `_mount`, `_advance`, `_clear_obstacle`, `_climb`), confirming each step
  against the save block so an interrupted walk is caught.
- `map_graph.py` is the learned world graph the travel loop routes over. `class MapGraph` holds
  `adj` (walked borders, persisted), `gated` (edges blocked under a specific field-move set),
  `world` (the static `rowe_rom.world_edges`), and `passthrough`. `neighbors` unions walked and
  world edges. `route`/`_bfs` returns the first hop toward a destination and skips any edge whose
  stored gate equals the live field moves exactly, so gaining a move reopens the edge. `block`
  records a gate; `observe` records a walked border; `explore_hop`/`frontier_exhausted`/
  `gated_frontier` drive exploration.

### Battle and catching
- `battle_engine.py` chooses moves and switches from live battler data and the ROM move table.
  `rank_moves` and `choose_move` score effectiveness and damage (`expected_damage`, `effectiveness`,
  `immune`); `first_usable_slot` is the PP'd fallback; `best_switch`/`strongest_bench`/`outmatched`/
  `edge` handle switching; `weakening_move` picks the catch chip, excluding multi-turn/charging
  effects (`CHARGING_EFFECTS`).
- `catch.py` computes catch odds following the game's throw formula (`catch_chance`) and holds the
  policy for what gets a ball: `helper_slot`, `status_move_slot`, and `class Ledger` (`wants`,
  `record`).

### Decision loop
- `planner.py` is the objective ladder. `recommend` picks, in priority: a party short of six or a
  lowest attacker under the badge level cap means grind; all eight Hoenn gyms beaten means travel
  to Ever Grande `(0,8)` when a route exists, else hold a grind on the grass nearest where the
  party stands with the blocked hop named in the reason; an unbeaten gym reachable over the world
  edges means route to the nearest; no gym reachable means explore toward the nearest. Supporting:
  `unbeaten_gyms`, `nearest_gym`, `still_closed`/`closed_gyms`, `hops_from` (BFS over world edges
  plus walked borders under the live moves), `grind_map` (visited grass ranked by hops to the
  anchor then by ROM wild level under the cap), `blocked_grinds`, `planning_anchor`.
- `play.py` is the executor and the largest file. `class Player` holds the whole run:
  - Frame I/O and waits: `run`, `tap`, `loop`, `wait_until`, `press_until`.
  - Overworld dispatch: `overworld_step` is the per-tick router; `travel_toward`, `explore_step`,
    `collect_step`, `gym_step`, `demote_to_grind`, `grind_wild_top` are the goal handlers.
  - Map crossing: `_cross_to` fires a connection, warp, dive, or emerge for the next graph hop
    (`field_moves`, `_landing_rank`, `_after_cross`, `region`, `service_town`); `_persist_blocked`/
    `_border_open`/`_stuck_key` record a gate when a crossing cannot complete; `_dive_frontier` and
    `_reachable_grass_map`/`_grind_no_grass` handle the underwater frontier and the grassless hold.
  - Battle: `battle_step` is the single-step fight handler; `_comm_action` and `comm_wait`
    single-source the selection-script box dispatch (B at `comm 6`, steer at `comm 3`);
    `_advance_intro`, `_reach_fight`, `steer_move_cursor`, `confirm_move`, `pick_move`,
    `catch_plan`, `throw_ball`, `use_hp_item_in_battle`, `_open_wild_switch`, `party_menu_step`,
    `learn_step` carry the rest. Readiness and heal: `gym_ready`, `needs_heal`, `_retreat_warranted`,
    `lowest_lead`, `heal_bench_from_bag`.
  - Stall detection: `battle_signature`/`stall_check` raise `StopRequested` on a wedged battle so
    the supervisor relaunches, `_stall_dump` writes the fixture.
  - Status and goal: `write_status`, `check_goal`, `replan`, `read_goal`, `snapshot`,
    `keep_snapshot`, `GoalExit`, `hold_stale`.
  - Gym bookkeeping: `gym_stand`, `record_closed_gym`, `record_gym_loss`, `note_gym_loss`,
    `_close_signature`.
  - Team management: `fill_party`, `do_pc_swap`, `do_swap_order`, `teach_tms`, `teach_egg_moves`,
    `scoring_builds`, `refresh_wanted`, `next_leader_type`, `unbeaten_leaders`. Module-level
    scorers: `team_score`, `matchup`, `wanted_types`, `tm_assignments`, `egg_assignments`,
    `best_swap`, `best_fill`, `shopping_list`, `field_tools`, `service_towns`, `gym_routes`.
- `routines.py` is the multi-map errands built on nav. `class Errands`: `cross_edge`/`take_dive`/
  `take_warp`/`enter_warp`/`descend_gym` drive a map transition; `heal_at`/`talk_to_nurse` a Center
  run; `restock_at`/`buy_from_list`/`open_buy_list` a Mart; `swap_at_pc`/`withdraw_at_pc` the PC
  box; `challenge_leader`/`gym_sweep`/`follow_route` the gym fights and recorded puzzle routes;
  `collect_item` a ground item; `teach_tm_in_field`/`teach_egg_move_at_nurse`/`use_hp_item_in_field`
  the field uses; `lead_with`/`spend_skill_points` the party chores. `take_dive` surfaces by
  pressing B across the reachable tiles until the map changes, then A on the "surface?" prompt.

### Orchestration and config
- `run-grind.sh` is the supervisor loop described above.
- `gym_routes.json` holds solved press routes for the puzzle gyms (Fortree gates, Lavaridge holes,
  the Sootopolis ice approach).
- `swaps.json` holds admin-set party trade orders.

### ROM mechanics database
- `build_rom_db.py` builds `games/rowe/rowe_rom.db` from `rowe_rom.py`'s readers, so a mechanics
  question is a SQL query instead of an emulator boot: `species`, `moves`, `type_chart`,
  `abilities`, `evolutions`, `learnset_levelup`, `tm_list`/`tm_compat`, `egg_moves`, `wild_levels`,
  `trainers`. Regenerate after a ROM swap.

### Deploy gate and tooling
- `smoke.py` is the offline promotion gate: it boots frozen savestate fixtures and asserts the nav
  and battle behaviors a swap into the live streamer must not regress. A red check blocks the swap.
- `gen_nav_map.py` renders the map graph into this repo's `index.html`.
- `dexgen/gen_species.py` emits `dexgen/species.json`, the web Pokedex dump read straight off the
  ROM (base stats, types, abilities, evolution path, and per-slot wild-encounter data), reusing
  `rowe_rom.py` plus a species-name table it fingerprints at 0x40B558; `dexgen/probe_pokedex.py`
  is its scratch probe. Read-only on the ROM, so a dex lookup needs no emulator boot.
- `solve_sootopolis_ice.py` solves the thin-ice gym-8 floor into a press route.
- `lavaridge_watch.py`, `make_fortree_entry.py`, `find_best_state.py` are single-purpose helpers.

### Probes
One-off investigations, each reproducing a specific failure offline on a scratch copy of the state
so a fix is grounded before it ships: the Fortree rotating gates (`probe_fortree_*`), the Lavaridge
hole maze (`probe_lavaridge_bfs`), the Sootopolis entry and dive (`probe_sootopolis_*`,
`probe_dive_sootopolis`), surf dismounts and elevation, the wild-battle switch stall, the
double-battle stall, ice timing. They are kept rather than deleted so the reasoning behind each fix
stays readable.

### Tests
`test_*.py` are behavior pins, most run against the real ROM tables rather than mocks. Each docstring
names the live misplay it locks down: the action-grid wedge, the 0-PP selection-script loop, the
double-battle action gate, surf-dismount refusals, the exp-lead switch, catch policy, the objective
ladder, the endgame no-route hold. `smoke.py` is the gate that must be green before a swap; the unit
tests are the finer pins under it. `test_lead.py` and `test_retreat.py` are script-style (`python
test_lead.py` prints `ok`).

## Where to find a feature

- Next goal chosen: `planner.recommend`. Goal executed each tick: `play.Player.overworld_step`.
- Why a run ends (stall/wedge): `play.Player.stall_check` raising `StopRequested`; the supervisor
  loop in `run-grind.sh`.
- Pathing a walk: `nav.Grid.path` then `nav.Navigator.walk_to`. Crossing a map edge, warp, or dive:
  `routines.Errands.cross_edge`/`take_warp`/`take_dive`, driven from `play.Player._cross_to`.
- Picking a battle move or switch: `battle_engine.choose_move`/`best_switch`, called from
  `play.Player.battle_step`.
- The selection-script no-PP box: `play.Player._comm_action`/`comm_wait`.
- Whether to catch and with what ball: `catch.catch_chance` plus `play.Player.catch_plan`.
- Gym detection and the fight: `rowe_rom.gym_maps` (music id 0x14F), `planner.nearest_gym`,
  `routines.Errands.gym_sweep`/`challenge_leader`/`follow_route`, `play.Player.gym_step`.
- A puzzle gym's solved route: `gym_routes.json` replayed by `routines.Errands.follow_route`.
- The world routing graph: `rowe_rom.world_edges` (static, including `dive_script_edges`) merged
  into `map_graph.MapGraph`; a blocked edge is a gate in `map_graph.block`.
- The endgame after eight badges: `planner.recommend` travels to Ever Grande `(0,8)`, else holds a
  grind on the grass nearest `here`.
- Team building: `play.team_score`/`best_swap`/`tm_assignments`, applied by `play.Player.do_pc_swap`/
  `fill_party`/`teach_tms`.

## The world routing model

The planner and the executor route over the same graph, so the planner never calls a destination
reachable across a border the walk gave up on. `rowe_rom.world_edges()` is the full static graph,
every map routable before it is walked, built from the ROM's connection and warp tables plus
`dive_script_edges()`. The executor records walked borders into `map_graph.adj` and gates an edge
it could not cross into `map_graph.gated`, keyed on the field moves held at the time, so the gate
lifts the turn a new move lands. `hops_from` ranks gyms and `grind_map` ranks grass over this graph.
A grind anchors on the next gym (or, in the post-badge no-route hold, on where the party stands) so
a restock detour in a service town cannot drag the grind onto the grass that town happens to sit
next to.

Sootopolis and gym 8 reach the graph through the dive edge. The entrance is not a connection or a
plain warp; it is a `setdivewarp` in the map's ON_DIVE_WARP script that fires when the player
surfaces in underwater Sootopolis. `world_edges()` parses that script table and emits the dive
edge, so a surface dive reaches the underwater route, a warp reaches underwater Sootopolis, and
surfacing there runs the `setdivewarp` that lands the party in the city.

## Building and running

The emulator, the ROM, and the runtime state are not in this repo. To run the agent:

1. Build mGBA 0.10.x as a shared library with the Python binding into `agent/mgba-build/`, and
   compile `agent/mgba-stubs.c` to `mgba-stubs.so` for the symbols an ffmpeg-less build omits.
2. Supply your own ROWE v2.1b ROM at the path pinned in `emu_boot.py`.
3. Create a venv and install the Python deps (cffi, Pillow, numpy). Use `agent/.venv/bin/python`,
   never system `python3`, since the venv holds the mgba binding.
4. Provide a starting save state under `agent/states/`.
5. `agent/run-grind.sh [hours]` supervises, or `.venv/bin/python agent/play.py --state <state.ss>
   --no-stream` runs one executor without the HLS push.

The code reads one specific ROM build. The fingerprinted offsets in `rowe_rom.py` and the addresses
in `rowe_symbols.py` will not match a different build or a different hack.
